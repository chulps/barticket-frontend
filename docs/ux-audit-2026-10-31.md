# Workflow visual audit — 2026-10-31

This pass used isolated browser fixtures, denied all external network requests, and asserted GET-only API traffic. It did not read or mutate production tickets, shifts, payroll or provider accounts.

## Matrix

English and Japanese were each exercised at 320×900 and 1280×900. Four scenarios passed and produced 36 full-page captures. Source baseline was frontend `49c06c1`; later targeted receivables checks used main `7e526fd` plus the presentation fix.

| Screen/state | Evidence and result |
| --- | --- |
| Tickets list and selected ticket | Ticket selection and detail render; quantity/subtotal, Add and Close remain reachable. Phone detail uses its own full-width screen. |
| Schedule | Upcoming and past-plan cards retain dates, assignment, unknown hours and source information. Both locales stack on phones and use horizontal fields on desktop. |
| Receivables | Long mixed EN/JP customer name, reason and note exposed issue #296: oversized/clipped English heading, narrow card fields and raw `pay_later` code. Targeted fix and regression follow this audit. |
| Later-payment dialog | Existing amount/method/confirm/cancel presentation captured without confirming payment. No provider or payment request was sent. |
| Analytics | All-time controls, currency summaries, existing bar/donut charts and empty sold-item/ticket states captured. No new chart type is proposed. |
| Current shift/time clock | Current punch, business date and management sections render in both locales. |
| Close review with open ticket | Blocker, affected ticket and automatic-clock-out explanation appear; confirmation remains disabled. No shift close was attempted. |
| No current shift/start screen | Explicit no-shift state and Start Shift action render. Opening was not submitted in this visual pass. |

Representative phone and desktop captures were visually inspected, including English/ Japanese schedules, ticket detail, Analytics, start screen, close blockers and receivables. Automated root overflow checks alone missed the clipped heading; the focused regression checks heading and body dimensions as well as card bounds.

## Acceptance boundary

This completes the above fixture visual matrix, not every end-to-end business outcome. Real shift open/close success, device push permission/delivery/taps, owner provider onboarding and production connection latency were not validated here. Existing functional suites and focused API integration tests provide separate evidence; a screenshot is not proof of a committed financial action. Final integrated Admin/Profile visual acceptance and the tracked source/provider/device requirements remain separate from this pass.
